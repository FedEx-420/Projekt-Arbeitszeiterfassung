# Fixed-page PDF preview and device files v904

Replaces the effective invoice, customer work-report, individual work-order and time-account print routes with real, client-generated A4 PDF files. The in-app dialog renders the same bytes that its download link supplies; legacy invoice tables no longer reflow into a narrow phone viewport. Closing the dialog returns to the existing application without a new sign-in.

The safe-area-aware toolbar exposes Close, PDF download and native file sharing. The PDF File and blob URL are prepared before the user clicks: native sharing is invoked directly inside the click handler, preserving iOS user activation. On iPhone/iPad, printing is offered through the native PDF share sheet rather than relying on window.print from an HTML popup. Unsupported file-sharing capabilities offer a real PDF-open/download fallback. Generation and rendering failures are explained visibly; a rendering failure does not disable an already generated file. Desktop printing remains optional.

PDFs preserve customer addresses, every participating employee and time segment, documentation, priced labor/material positions, totals and work-report signatures. The model reuses the existing current-open/frozen-invoiced price rules and captures a snapshot before loading a company logo. Previewing or downloading never marks work orders as invoiced. Multi-year time-account print reports retain their year/month grouping and absence data. Existing offer/planning downloads are unchanged.

The viewer uses the already bundled Mozilla PDF.js 6.4.299 reader, matching worker and standard fonts, and the existing PDF-lib 1.17.1 generator. No new third-party service, remote upload, account, database migration or permission is introduced. Service-worker handling ignores blob URLs and remains restricted to same-origin public assets. All existing session keys, backend configuration and stored records remain untouched.

Validation used synthetic records only: generated four documents totaling 28 pages, checked 41,161 characters against paper bounds and visually reviewed rendered pages. Actual invoice-download bytes were saved through the browser UI and checked for employee names, times, labor prices and totals. Portrait 390×844 and landscape 852×393 views, a seven-page preview, close/reopen and console checks passed. Navigation, safe-area, session, remembered-device and time-account regression checks passed. Native sharing was tested at the synchronous handler boundary with a capability stub; a physical iPhone share sheet, AirPrint printer and mobile Safari hardware were not available for direct verification.
