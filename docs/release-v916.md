# v916 – Katalogimport bei Datenbank-Zeitüberschreitung

Der bisherige Browser sendete bis zu 1000 geprüfte Artikel in einer einzigen transaktionalen RPC. Die Oberfläche sendet nun höchstens 25 Artikel nacheinander an denselben unveränderten v911-Endpunkt. Bei einer ausdrücklich bestätigten PostgreSQL-Statement-Zeitüberschreitung (57014 und passender Meldung) wird nur das zurückgerollte Paket halbiert, bis mindestens ein Artikel übrig bleibt. Andere Fehler, Abbrüche, Netzwerkfehler oder fehlende/uneindeutige Serverbestätigungen lösen keine automatische Wiederholung aus.

Jedes Paket muss Version, Firma, Preisquelle sowie plausible Artikelanzahlen bestätigen. Fortschritt zählt nur bestätigte Pakete. Die Bestätigung erklärt vorab, dass es jetzt mehrere Transaktionen gibt: Bei Unterbrechungen bleiben frühere bestätigte Pakete gespeichert. Ihre Artikel werden abgewählt; die übrigen Angaben bleiben zur erneuten Prüfung erhalten. Die Materialliste wird neu geladen und eine neue Vorschau/Bestätigung ist nötig. Bei einem Netzwerkausfall kann der letzte unbestätigte Teil bereits gespeichert sein; darauf weist die Oberfläche hin. Der vorhandene Lieferant-/Artikelnummer-Abgleich und Versionsschutz im Server bleiben erhalten. Firmen-/Kontowechsel stoppen weitere Pakete, auch bei einem Wechsel zurück zum Ausgangskonto.

Keine Änderung an Datenbankfunktionen, Timeouts, RLS, Konten oder bestehenden Daten. Live-Ursache (z. B. Lock, Index oder RLS-Laufzeit) nicht bestätigt: Beide verbundenen Supabase-Konten lieferten keine Projekte. Der Frontend-Fix begrenzt die Dauer pro Anfrage; ein Timeout bei einem einzelnen Artikel verlangt weiterhin eine Datenbankprüfung.

Verifikation: isolierte Tests für adaptive Paketgröße, keine Doppelbestätigung, Abbruch bei einem Artikel, kein Retry bei Netzwerk-/anderen Abbruchfehlern, Bestätigungsprüfung und Firmenwechsel. Browserprüfung: 71 synthetische Artikel trotz simulierten Timeouts vollständig übernommen; Teilfehler nach 25 von 51 Artikeln, verbleibende 26 erneut geprüft und ohne doppelte Artikel abgeschlossen. Bestehende Katalogfilter-/Mobiltests unverändert erfolgreich. Keine realen Artikel als Test angelegt.
